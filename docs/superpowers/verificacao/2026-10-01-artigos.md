# Verificação dos artigos

Implementação em app-web-artigos, branch artigos a partir de 7523cd9. O checkout
app-web em fix/taxa-gratuita e seus três arquivos modificados foram preservados.

## Evidências

- API: 862 testes em 78 suítes, incluindo contratos com PostgreSQL 16 descartável,
  migrações reais do engine e papel bc_api_leitura. Lint e build aprovados.
- Web: pnpm verificar aprovado, 805 testes em 95 arquivos, lint e TypeScript.
- Build de produção aprovado contra API fixture exclusivamente local, sem ler
  banco real ou gerar textos pagos. Fixture não faz parte do código publicado.
- PNG real decodificado nos testes: 1200x675, 1200x900 e 1200x1200.
- Servidor standalone: script verificar-artigos.mjs aprovado. Artigo ausente e
  paginação excedida respondem 404 para navegador e Googlebot-News; busca noindex
  sem canonical herdado da home. XML interpretado com parser, robots anuncia os mapas.
- Navegador: capa, formulário de busca e detalhe inspecionados a 390 e 1280 pixels.
  Sem rolagem horizontal. Imagem principal carregada, JSON-LD e dados visíveis
  consistentes. A prévia usou conteúdo explicitamente identificado como demonstração.
- Revisões independentes da API, páginas e SEO aprovadas após os ajustes abaixo.

## Decisões tomadas na continuação

- Temporários dentro dos repositórios no disco principal. Novos commits sem
  atribuição ao Claude; branches e trabalho anterior preservados.
- ts_headline pode recortar a palavra inicial: o contrato verifica destaque e
  conteúdo útil sem impor uma abertura que o Postgres não promete.
- Filtro opcional concursoSlug usa igualdade canônica parametrizada para o link
  da ficha ao artigo; aliases são resolvidos pela página antes dessa consulta.
- A API rejeita byte nulo com 422 antes do banco. Ranking foi testado com dois
  resultados e ordens diferentes entre recentes e relevantes.
- Sitemap histórico dedicado evita somar até 50000 artigos às URLs preexistentes.
  A API ainda limita seu mapa aos 50000 artigos mais recentes; ultrapassar esse
  volume exigirá paginação adicional do endpoint.
- Falha da API no sitemap retorna 503 com Retry-After. Ausência real retorna XML
  vazio. Partes News usam prefixos do hash do slug, evitando deslocamento após
  despublicação; uma parte que cresce além de 1000 retorna 503 até o robô reler o
  índice atualizado com suas subdivisões.
- Sem loading.tsx acima das consultas editoriais, para preservar 404 real. O link
  editorial complementar da ficha usa Suspense próprio e não bloqueia a ficha.
- Busca noindex não herda canonical da home. Texto e trechos permanecem escapados.

## Antes de ativar

Implantar engine, API e web nessa ordem. A pauta permanece desligada. Resumos
periódicos ainda precisam de validação com dados reais, incluindo o recorte de
natureza dos concursos; não houve implantação nem ativação nesta entrega.
Rich Results Test e inspeção Search Console precisam das URLs públicas após deploy.
